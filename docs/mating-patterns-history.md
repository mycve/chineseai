### 已验证的搜索修正

此前 v57 的 fast 构建通过；完整回归 415 项通过、4 项跳过，另行启用的 CPU/CUDA 目标条件策略、WDL 与距离一致性检查通过。回归覆盖确认名单的终局识别与反例、目标证明的全部合法应对、历史校验、`searchmoves` 限制、条件距离保留及旧模型显式裁剪迁移。

- 卧槽马、挂角马、钓鱼马、高钓马的几何先验改用空盘马步距离。原先用直线距离，可能奖励实际上离目标更远的跳法：用户残局中 `h5f6` 将到高钓马点的最少跳数从 2 增为 3，而 `h5f4` 减为 1。空盘距离忽略蹩腿，仅作乐观下界和先验，不冒充杀棋证明。
- 普通必胜的证明距离与目标条件下的 MLH 估计分开使用。证明存在普通短杀，不能把尚未完成的目标路线也压成同样短。胜势明确后，以 `P_goal / (1 + confidence × MLH.slope × M)` 比较目标收益，再与原 WDL 分量组合；`confidence` 使用已有 MLH 胜势门槛。前期和非优势候选维持原目标效用；关闭 MLH 或将其 MaxEffect 设为 0，也关闭新增时间项。
- 从真实匹配的将死节点向上传播目标证明。执行方需要一条已证明的合法路线，对手回合必须覆盖全部合法应对；同步维护目标杀距上下界。找到一条较长目标路线后，预算继续用于可能更短的路线，不能立即停止或一直重复访问已无改进空间的证明分支。最终选着与策略标签优先最短的已知目标证明。
- UCI 与自博弈工作区保留完整证明分支。复用要求目标、执行方、完整历史及当前位置一致，且遵守 `searchmoves`；对手回合不由此选择配合走法。后续可被更短证明替换。已经保留的证明路径，其剩余步数上界逐手递减。UCI 输出 `mating proof plies=… source=goal-proof`，区别于未证明的高网络分数。尚无证明时仍使用模型和 MCTS，不能保证所有局面都不再空转。

## 2026-11-03（前一轮）：减少强化绕路，目标失败与棋局结果分开

本轮只调整训练监督和统计，生产 MCTS、UCI 选着、目标概率头和 WDL 含义不变。没有增加网络头或可调参数，模型 v56、经验池 v47、优化器与配置均可继续使用；不必清空已有训练成果。

成功轨迹的额外策略模仿权重改为 `strength × policy_weight × 0.997^T`，`T` 为该样本到实际终局的剩余半回合数。只有执行方实际以目标杀法获胜的动作参与，仍按目标类别平衡，类别归一化不抵消时间权重。100 半回合约保留 0.74、200 半回合约保留 0.55 的模仿权重，既降低远期成功前缀的强化，也保留开局的目标信号。未知距离沿用原权重，不猜测完成时间；常规 MCTS 策略标签、目标成败标签、WDL 和 MLH 标签均不因此重写。已有经验池中距离已知的成功轨迹也直接采用此权重。

这不是对循环的精确识别：长但必要的准备也会降权，短期内无法保证消除残局空转。它修正的是“很长的成功轨迹与短成功轨迹同等强化”的训练倾向，后续仍需用完整对局验证命中率和收束效率。

必要子力不足时，目标轨迹以失败结算：此前资源仍满足的前缀得到 `goal_target=0, goal_weight=1`，失去资源后的样本关闭目标监督和条件策略，继续普通争胜。即使后续普通棋因搜索异常没有获得结果，已确认的资源失败也不再丢失。低网络概率、几步没进展或暂未搜到目标都不能视作不可达。整盘不因目标失败而认输或停止，WDL 继续使用实际结果；若以后单独收集不训练 WDL 的目标任务，才可以在确定目标失败后截断，不能将这种截断伪造成真实负局。

控制台新增 `命中均长`，单位是从本盘指令起点到目标将死的半回合。TensorBoard 每类目标新增 `mating/goal/<目标名>/mean_success_plies`；失败和未知不进入成功长度的分母。比较时同时看命中率和命中均长，避免把“长对局超时失败”误当成效率提升；不同目标和起始局面的分布也会影响均长。

本轮还验证并撤回了“每层 MCTS 目标回传乘 0.997、成功标签改为折扣成功值”的整套候选。冻结用户提供的 v56 权重，使用既定 32 个局面 ×14 目标、1024 次模拟、强度 0.4、120 半回合预算，命中从 24/448 下降为 12/448；普通模式的全部着法和计分完全一致。对照来自此前 240 半回合报告的前 120 半回合，超过该点的终局按截断处理，两组局面键完全一致。用户高钓马三个完整历史残局、20000 次模拟的目标完成长度从 96/14/16 变为 110/24/16 半回合。旧目标头没有学过折扣回报，这不证明重新训练该任务一定无效，但不支持将其当作现有权重的即时搜索补丁，故未合入。当前保留的策略模仿降权并未完成新一轮服务器训练验证，不能宣称已根治乱走。

最终代码完整回归 412 项通过、4 项跳过，fast 构建通过。重编译后，同一权重、强度 0.4、20000 次模拟的三个用户残局重新得到 96/14/16 半回合；普通和目标模式的完整棋谱、计分及模拟数均与修改前一致，确认搜索实验已撤回。原权重 SHA256 未变。新增检查覆盖成功轨迹效率降权而原标签不变、目标失败后仍可获得真实 WDL 胜局、成功长度的统计合并与输出。

## 固定名单与识别范围

所有命中都要求真实将死：双方将帅存在，轮走方被将军且没有合法应着。仅有某种站位、子力数量或网络高概率不算完成目标。杀法是最终致胜机制，一步杀、两步杀是距离，不用固定步数排除某种杀法。

| UCI 目标 | 名称 | 工程判定范围 |
| --- | --- | --- |
| `double-cannon` | 重炮 | 将军炮与敌将同线，唯一炮架为己方另一炮，支持横向和纵向。 |
| `iron-bolt` | 铁门栓 | 中炮实际牵制中路防守子，车或兵在底线、肋道将死。 |
| `horse-cannon` | 马后炮 | 马是将军炮的唯一炮架，与将相距两格并实际封锁逃格。 |
| `white-faced-general` | 白脸将 | 己将利用将帅不能照面的规则，实际封住敌将逃路。 |
| `elbow-horse` | 卧槽马 | 黑宫受攻时马在 `c8/g8` 直接将军；红宫为 `c1/g1`。 |
| `palace-corner-horse` | 挂角马 | 黑宫受攻时马在 `d7/f7` 直接将军；红宫为 `d2/f2`。 |
| `angler-horse` | 钓鱼马 | 黑宫受攻时马在 `c7/g7`，实际封逃；红宫为 `c2/g2`。 |
| `octagonal-horse` | 八角马 | 马与敌将占据九宫对角，马实际封逃；前角、底角均可。 |
| `high-angler-horse` | 高钓马／侧面虎 | 黑宫受攻时马在 `c6/g6`，其他子将军，该马实际封逃；红宫为 `c3/g3`。 |

中文名称、连字符键、下划线键可用于 CLI/UCI；“铁门闩”“侧面虎”作为对应别名。TOML 使用下划线枚举名，例如 `high_angler_horse`。`none` 表示普通争胜。

GUI 的 `MatingTarget` 为 UCI `combo` 下拉框：普通争胜及 11 种中文杀法名，一次选一种。默认铁门栓、强度 0.8，开箱启用；手动发送英文键仍可用。更新引擎后需让 GUI 重新读取选项列表；若 GUI 保存了旧的关闭设置，可恢复默认。

标签可以重叠，例如双马饮泉与卧槽马、钓鱼马；不用互斥 softmax 强行分桶。“实际封逃”通过执行敌将的伪合法宫内走子后，检查是否仅该支持子阻止此着来认定；重复控制可能不计，属于明确的保守子集。铁门栓中炮另需验证真实牵制作用。未命中不代表没有其他杀法。

困毙单独记录为 `Stalemate`，不算 11 类目标成功。长将、规则判负、缺将、步数截断、仅有搜索证明都不冒充真实将死。

## 开局输入目标

```text
uci
setoption name EvalFile value multi-v58.safetensors
isready
ucinewgame
position startpos
go nodes 800
```

收到 `readyok` 后搜索，默认已经执行铁门栓目标。切换杀法只需 `setoption name MatingTarget value 马后炮`。`MatingSide` 默认 `auto`：首次 `go` 绑定本盘引擎执子方，之后换根不换执行方，`ucinewgame` 后重新绑定；也可显式指定 `red`/`black`。目标与强度跨 `position`、回合及 `ucinewgame` 保留。强度为 `0..1`，默认 0.8，设 0 或选普通争胜均关闭目标。CLI 的 `az-search` 同样默认铁门栓、0.8，可显式用 `--mating-target none` 做普通对照。CLI 示例：

```text
chineseai az-search multi-v58.safetensors 800 1.0 --mating-target 高钓马 --mating-strength 0.8 --mating-side red startpos
chineseai mate-classify "3aka3/9/9/4C4/9/4C4/9/9/9/4K4 b"
```

策略从第一步读取目标残差编码，配合受限布局先验；目标价值头预测固定执行方最终完成指令的概率。MCTS 在执行方节点使用 `(1 - strength) × 普通 Q + strength × (2 × 目标收益 - 1) + PUCT 探索项`，目标概率固定执行方视角回传、不取反。非明确胜势时目标收益等于成功概率；明确胜势时按上文公式加入完成时间偏好。强度 0 为普通争胜，1 时以指定杀法为主要搜索收益，WDL 仍用于同分择优和避开已证明败着；默认 0.8 保留部分争胜权衡。目标模式也保留已有 MLH 有界收尾加分，仅在胜负把握超过既有门槛时启用。最终选着优先最短的已知目标证明。对手按普通 WDL 搜索，不配合执行目标。

关闭目标或必要子力不足时恢复普通策略：重炮至少两炮，马后炮需马炮，双马饮泉需两马，双车错需两车；资源条件只用于认定明确不可达，不把搜索暂未找到当作不可能。目标几何先验只改变策略 logits，不能作为成功标签或杀法证明。若已展开的所有可选路线均被确认无法完成目标，也恢复普通争胜。

带目标也复用网络分支缓存、使用原 KLD 收敛停止。网络缓存要求目标、执行方、强度、参数及完整历史一致。执行方根节点证明普通必胜后，仍可在原 simulations、KLD 和时间预算内继续寻找目标路线；已发现真实的指定杀法一手将死则立即停。目标概率是估计；严格目标证明只在已展开的树内按执行方 OR、对手 AND 传播，不另开证明搜索预算。跨回合证明缓存按前述规则独立验证。

## 自博弈采样

新生成的配置已默认启用目标混合与 0.8 强度；下面为显式写法。顶层字段必须放在 `[mating_goal]` 之前：

```toml
format_version = 34
selfplay_opening_book = "book.pgn.gz"
mating_goal_mix = true
train_value_weight = 1.0
train_policy_weight = 1.0
mating_loss_weight = 0.1
goal_loss_weight = 0.1

[mating_goal]
target = "iron_bolt"
side = "red"
strength = 0.8
```

- `mating_goal_mix=true`：约 10% 对局普通争胜，其余 90% 在当前起局仍有必要子力的确认目标中均匀采样；不按网络预测成功率筛选，避免困难目标失去训练机会。若全部目标都已缺必要资源，则恢复普通争胜。
- `mating_goal_mix=false`：固定使用 `[mating_goal].target`。
- 执行方固定用 `[mating_goal].side`，不随机红黑、不增加随机选方开关。canonical 编码共享双方参数，固定执行方的整盘数据也含执行方及对手两种回合。
- 每盘只指定一方执行目标，目标、执行方和强度盘内不变。对手正常争胜。空开局库从标准初始局面开始。

GUI 自动绑定本盘执子方与自博弈固定执行方是入口层约定；都不随机选红黑，也不在搜索子节点中切换执行方。显式保存的配置值优先于新默认，不擅自覆盖用户选择的普通争胜或强度 0。

开局库是既有的可选 FEN 起局来源，不是新增的残局模式。沿用已有开局库即可从所选局面开始执行目标；FEN 之前的着法不属于该盘目标训练样本。这里的混合采样检查只避免为缺炮、缺马等局面分配已明确不可达的目标；不改变开局库配置。手动固定指定目标不被重新随机分配，仍按原规则在不可达时正常下。

自博弈把带指令的 MCTS 策略训练回条件策略，尚无终局标签时也可以学习策略。最终真实完成指定杀法则固定执行方目标标签为 1，其他已观察结果为 0；双方此前局面使用相同执行方视角。正常用尽自博弈步数预算仍未完成指令，按本盘目标失败监督：目标标签 0、有效权重 1；WDL、辅助杀形和未获证明的终局距离仍保持未知并屏蔽。搜索异常等未知结果，或样本时刻已无必要子力，目标价值权重仍为 0。不能把旧策略标签事后重标成另一条指令。

搜索、最终选着及温度采样采用同一目标策略分布。普通已证必胜着与未证明的目标路线共同探索，不能在最终选着或采样时再强行过滤掉后者；已证明败着在有其他选择时排后，真实目标一手将死优先。网络目标概率的微小差别不再把普通必胜着之间的策略标签强行压成单点。若目标模式主动放弃了普通必胜路线，WDL 按实际胜负监督，不能再用该普通证明覆盖结果；普通模式仍保留证明监督。未选择的普通杀着的证明距离也不能当成目标路线的距离标签。

为利用稀少正例，训练增加**成功轨迹策略监督**：仅使用原指令实际完成、当前轮到执行方、且记录了实际执行动作的样本；从开局到终局的有效前缀均可参与。普通 MCTS 策略监督与成功轨迹监督各占一半，成功部分按偏好强度和完成距离加权，再按本批各成功目标的样本数平衡，保留效率差异。没有成功轨迹时沿用原策略损失；失败、未知、对手回合及无动作记录的样本不会冒充示范。WDL、目标价值 BCE、辅助杀法和距离监督保持原样本分布；不给其他指令伪造成功轨迹。不新增采样或损失配置项。

这一实现借鉴重用自身成功经验的思路（[Self-Imitation Learning 原论文](https://arxiv.org/abs/1806.05635)），论文仅为方法动机；本项目的收益仍须用象棋对局验证。重复利用轨迹不增加独立成功对局数。某类从未成功过，就仍缺少该类正例，不能据此宣称已能从所有开局泛化。


11 个辅助头读出共享棋盘表示，预测当前行棋方最终以相应杀法获胜的概率，使用稳定 sigmoid BCE。`mating_loss_weight` 控制该辅助任务；`goal_loss_weight` 控制条件目标价值任务。目标损失按有效目标样本的权重总和归一化，不被普通对局、异常未知或资源不足样本的比例稀释；正常步数超时作为有效目标失败参与，停用和无标签时仍断开该损失的梯度。正负样本均保持真实分布，目标 CE 下降不等于执行成功率提高。

当前条件表示沿用 v56 引入的轻量乘性门控：基础局面表示为 `h`，执行方/目标对应的一行为 `g`，强度为 `s`，则 `u = h * (1 + s * tanh(goal_scale[g]))`。WDL、距离头读取 `u`；目标价值头和执行方策略读取 `ReLU(u + s * goal_hidden[g])`。对手的策略仍读取基础 `h`，对手 WDL 读取有指令条件的 `u`，学习对手正常争胜时这一对局策略的胜负。辅助杀法头继续读取基础 `h`。没有目标或必要资源已丢失时全部恢复基础表示。

原先只有加性目标偏移，在 ReLU 激活区间不变时，线性目标价值头对不同目标主要只能改变偏置。乘性门控允许重炮、马类等目标分别选择局面特征；它同时接受策略、WDL、距离和目标终局损失的梯度，尚未完成对局时也能通过 MCTS 策略监督学习。裁剪后的门控矩阵为 `22 * hidden_size` 个参数，不增加配置项；CPU 在权重发布时预计算 tanh，每个节点只读取一行，不增加搜索或证明预算。新模型门控从零初始化；v56 迁移保留已经学到的门控，v54/v55 缺失的门控补零。

## 统计与效果判断

控制台只列 11 类命名杀法，显示批内总局数、实际将死、困毙、未知、各目标尝试／成功／未知及“目标执行红/黑”数量。杀法可重叠，计数不应相加作为总盘数。

TensorBoard：`mating/goal/{名称}/{attempts,successes,unknown,success_rate}`、`mating/goal_side/{red,black}/attempts`，累计对应 `mating_total`。训练和留出集记录 `goal_{bce,samples,target_rate,pred_mean,brier}`，并记录 `goal_imitation_ce`、`goal_imitation_samples`（仅原指令成功执行方的真实动作）。控制台新增“轨迹CE/样本数”，以便观察成功轨迹是否进入训练。目标率分母包括失败和未知尝试。

控制台另分组报告“目标局胜/负/和/未知”“普通局红/黑/和/未知”，目标局一律按指定执行方视角计数。目标局胜率为执行方实际胜局 / 目标局总数；胜局命中率为指定杀法成功局 / 执行方实际胜局。未知实际结果单列，不当成和棋；杀形未知与胜负未知分别统计。这样可以区分“执行方赢不了”和“能赢但没有完成指定杀法”。

TensorBoard 对每个目标记录 `wins/losses/draws/unfinished/win_rate/success_given_win`；汇总见 `mating/goal_owner/*`，普通对局见 `mating/ordinary/*`，累计仍对应 `mating_total`。分组统计本身不改变目标函数或温度；本轮精简名单后的模型与回放变化见迁移章节，按用户选择重新训练。

全局杀法率包含双方，指令成功率只算指定执行方，两者不能直接比较。应在同模型、同开局上对比无指令和指定指令的执行方胜率、命中率，同时记录平均模拟数、每秒模拟数和对局长度。CE 下降及条件策略变化不等于已学会从开局稳定执行指定杀法。

### 2026-11-03：区分真实循环与空转，并补上超时失败监督

评测报告新增 `initial_cycle_count`、`initial_longest_cycle_plies`，按完整棋子布局和行棋方统计真实回访。用户这盘到第 149、169、197 半回合，累计回访数均为 3，最大回访间隔均为 4 半回合；第 149 到 197 半回合之间没有新的完整局面回访。此段主要是多个子轮换挪动、局面每次略有变化的近似循环，三次重复规则无法仅凭外观相似将其结束。没有改动正式重复判定，也没有把近似局面强制判和。

另确认一处训练反馈缺口：此前正常达到 `max_plies` 的目标对局全部屏蔽目标损失，导致这批长期未完成指令的轨迹没有提供目标失败监督。现明确目标任务为“在本盘自博弈步数预算内完成指定杀法”，正常预算耗尽记目标失败，`goal_target=0`、必要资源仍存在的前缀 `goal_weight=1`。只有实际将死并匹配原指令才是目标成功。最后允许的一手若已将死，仍按真实结果计分，不能记超时。

胜负和杀形没有因此被补造成终局：正常超时的 WDL 仍为未知，辅助杀形标签仍屏蔽，未获证明的距离标签仍屏蔽；搜索失败等异常仍不提供目标监督。原始指令和成功轨迹策略监督规则保持不变。

统计上，每类目标的“未知”不再包括已确认用尽预算的本盘失败；总 `cutoff`、全局杀形未知和“目标局胜/负/和/未知”中的胜负未知仍正常计数。因此这些“未知”字段不应相互等同。目标监督样本数会增加、有效正例比例可能降低，新旧目标 CE 不宜直接解释为能力升降。

模型、优化器和回放格式不变。旧经验池中的超时样本仍保持原来的零目标权重，不猜测它们究竟来自超时还是异常；新采集的正常超时对局开始提供负监督，可沿用现有检查点续跑。此改动修正学习反馈，不会即时修复旧权重，也没有完成新训练模型的长循环改善验证。

新增/加强检查覆盖完整局面与行棋方的循环统计、正常超时目标失败与 WDL/杀形/距离屏蔽、异常未知继续屏蔽，以及无 WDL 标签时有效目标负样本可压低目标预测。完整回归 411 项通过、4 项跳过。

## 当前设计取舍与待验证项

- 红黑执行方随机不是正确编码的必要条件，已移除该功能。固定选方可能存在先后手分布差异，评价目标效果时使用同执行方、同开局的配对对照。
- v56 已让 WDL、距离估计也读取目标门控，减少不同指令策略结果被无条件平均的问题。WDL 的标签仍是胜/和/负，应继续比较各目标下的校准，不能把结构接通视为训练已经有效。
- 远期目标的成功监督稀疏，失败预测准确也能降低 BCE。支持 11 类不表示同时均匀训练 11 类就有足够正例；应看正例覆盖、常数频率基线及同开局指令增益，区分手写布局先验与学到的长程控制。
- v56 已将目标损失改为按有效权重总和归一化，`goal_loss_weight` 相同数值的实际贡献会比旧版本更高，幅度取决于有效目标样本比例。例如有效占比约 50% 时，目标分支相对旧实现约为两倍；建议先保留 0.1 做对照，不同时改动多个训练权重。
- 已移除普通胜负证明对目标最终选着、温度采样的硬覆盖，以及按最高网络目标估计值压成单点的筛选。目标成功率仍是估计，不能当作杀法证明；强度越高，越可能为目标放弃普通必胜着。
- Arena 当前评估普通争胜，`best` 的选取不衡量杀法指令命中率；自博弈使用最新训练模型，不受 Promote/Reject 阻断。验证控制效果时应使用目标指标配对评估训练检查点，不能仅以 Arena 的 Promote 判定目标能力更好。
