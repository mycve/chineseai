# 自博弈采样与网络改造路线图

## 目标

在固定自博弈模拟量和训练算力下，提高标准初始局面、开局分支及中残局的综合棋力，同时保持 CPU 叶节点推理吞吐。所有结构变更必须通过对照实验，不以训练损失单独作为合入依据。

## 决策指标

- 标准初始局面、固定开局集、固定中残局集的配对 Arena Elo 与置信区间。
- 各绝对手数阶段及起点来源的 value RMSE、相关系数、校准误差和 policy CE。
- 每百万次 MCTS 模拟产生的独立终局数及训练样本数。
- 叶节点推理吞吐、整局 simulations/s、模型尺寸和训练吞吐。
- 局面池快照年龄、来源比例、阶段比例及稀疏参数表覆盖率。

## 资料依据与比例解释

- 原始 AlphaZero 从标准初始局面生成完整自博弈，证明“只从初始局面出发”在极大算力下可以成功，但其探索主要集中在前若干手，不能据此推断有限算力下的深层局面覆盖已经充分。[Silver 等，2018](https://discovery.ucl.ac.uk/id/eprint/10069050/)
- Go-Exploit 直接研究 AlphaZero 的起点分布：从历史局面档案重启能访问更多深层状态、产生更多独立终局价值目标，并在 Connect Four 与 9x9 Go 上提高样本效率。其 9x9 Go 最佳配置保留 10% 标准初始局面；Connect Four 对初始局面概率扫描了 0%、1%、10%、25%，不同档案策略的最优值并不完全相同。[Trudeau 与 Bowling，2023](https://arxiv.org/pdf/2302.12359)
- KataGo 使用另一种互补机制：约 2.5% 的局面分叉尝试替代着法，并让其中四分之一继续递归分叉；另有 5% 的对局采用异常开局。这支持“少量定向偏离正常自博弈分布”有价值，但这些数字不是初始/开局/中局三类起点的可直接移植比例。[Wu，2019](https://arxiv.org/abs/1902.10565)

因此不存在可直接套用于中国象棋的公认比例。当前 A/B/C 不是引用文献中的固定配方，而是以 Go-Exploit 的 10% 初始局面结果作为低端参考，同时保留 30% 开局覆盖，对 40%–60% 中局重启做等距扫描。最终比例必须由本项目固定算力、配对种子和三阶段 Arena 决定；训练损失或单一中残局指标不能单独定案。

## 里程碑

### M1：修正重启探索与局面池新鲜度

- 池化局面按局部手数重新启用短温度窗口；绝对手数仍用于阶段标签。
- 开局池和中局池按“近期代优先 + 全历史 reservoir 回填”采样。
- 配置、启动日志和边界测试覆盖新行为。
- 验收：全量测试通过；关闭新配置时行为可恢复；空池和近期池不足时安全回退。

### M2：历史敏感的局面身份与可观测性

- 局面池去重键纳入规则历史摘要，避免同盘面不同长将/长捉状态被折叠。
- 记录实际起点来源、起点绝对手数、快照年龄及重启温度统计。
- 统计 value threat、policy sparse、policy tactical 表项的命中与更新覆盖率。
- 验收：同棋盘不同规则历史可共存；统计可从日志和 TensorBoard 读取。

### M3：采样工程卫生与低成本旁证

- A：初始/开局/中局 = 30/30/40。
- B：初始/开局/中局 = 20/30/50。
- C：初始/开局/中局 = 10/30/60。
- 固定模型、模拟次数、训练样本数、随机种子组和评测局面集。
- 验收：单种子短筛只用于排除明显异常，并确认来源、阶段和吞吐统计合理；不再把大规模比例搜索作为提升模型上限的主线。

共同的 hidden=256 `best.safetensors` 和共同起点池用于完成单种子 10-update 短筛。共同池含 128 个开局快照和 128 个带完整规则历史的中局快照，避免空池使早期更新退化为 100% 标准局面。原定三比例 × 三种子 × 100 updates 的确认网格暂停；只有网络主线出现来源偏科或明显中残局退化时，才恢复针对性采样实验。

Rust 实验二进制统一使用 Cargo `fast` profile（thin LTO、16 codegen units、增量编译）；同一轮对照不得混用 `release` 与 `fast`，吞吐基准必须注明 profile。

### M4：轻量网络容量消融

- 基线：当前单层累加主干。
- 候选一（已完成首筛）：累加器归一化后增加 `h → rank → h` 的低秩残差层；rank=32 用于验证表达增益，rank=8/16/32 用于测量推理成本。
- 候选二：对超大 exact policy 表进行低秩分解，并保留高频 residual。
- 候选三：增强低秩关系聚合，减少对 value threat 巨型嵌入表的依赖。
- 旧模型可无损升级：下投影随机初始化、上投影全零，升级瞬间价值和策略输出逐位不变；旧 safetensors 缺少残差字段时按 rank=0 加载。
- 验收：先做单变量实验；候选必须在可接受吞吐损失下提高固定算力 Elo、价值校准或固定标签策略命中率，训练损失不单独作为结论。

### M5：最终方案与迁移

- 固化起点比例、池采样、网络结构和评测配置。
- 升级模型/配置格式，提供旧模型处理策略。
- 完成完整回归、性能基准和训练启动文档。

## 当前状态

- M1 代码与回归已完成：局部重启温度和近期代优先采样已实现。固定算力效果由 M3 统一评估。
- M2 代码已完成：局面池使用棋盘与规则历史联合身份；日志与 TensorBoard 已记录起点来源、绝对手数、快照年龄、重启温度，以及训练子集的稀疏参数激活覆盖。该覆盖是“本批次可能收到梯度的行”的代理，不等同于跨更新累计参数更新率。
- M3 的单种子短筛已完成工程验证：三种比例都能按目标来源运行，增加中局起点会缩短对局并提高独立终局数，但没有固定 Arena 证据证明其提高模型上限。最终保留较保守的 30/30/40；三种子长期网格取消，采样只承担覆盖与诊断职责。
- M4 已完成两条候选首筛。低秩残差 rank=32 没有取得足以覆盖推理成本的收益；策略 tactical 中间因子改善固定 replay CE，但 4098 盘大样本 Arena 为 -1.9 Elo。二者都不设为默认结构。保留残差兼容/消融能力以及已验证的 tactical 因子预折叠推理优化。
- M5 已固化默认方案：新训练默认 hidden=256、residual rank=0，起点比例 30/30/40，局面池近期采样 75%/20 代，池化重启温度 0.6/8 ply；结构候选只有通过分来源 Arena、固定标签和吞吐三重门槛才可启用。

## 固定评测基线（2026-09-22）

- 模型：`best.safetensors`，hidden=256；所有消融从同一字节模型复制启动。
- 固定 Pikafish 标签抽样：`eval/pikafish-selfplay-5000-d20.sqlite`，种子 20260922，抽样 1000、有效 976，搜索 64 simulations。
- raw value：相关系数 0.921916，目标对预测校准斜率 1.170292，WDL-Q MAE 0.238049。
- 64-sim search value：相关系数 0.937081，校准斜率 1.183306，WDL-Q MAE 0.227051。
- 策略：raw prior top-1 37.9098%；search top-1/2/4/8 为 42.9303%/60.1434%/75.4098%/87.0902%。
- CPU 标准初始局面基准：800 simulations × 100 次，AVX2+FMA，162,231 simulations/s，4.931 ms/search。
- 三来源 Arena 已支持标准初始局面、固定开局书局面、带完整规则历史的固定中局快照，输出配对换色 Elo 及 95% 区间；同模型自检综合得分为 50%。

## 低秩残差首筛结果（2026-09-22）

- rank=0 与 rank=32 从相同 hidden=256 模型、相同随机种子、相同起点池和 800 simulations 开始，各训练 10 updates；稳定轮次的 Q RMSE 为 0.2350/0.2354，Q 相关系数为 0.9374/0.9379，policy KL 为 0.3599/0.3558。训练侧仅有微小、非一致改善。
- 优化后的中性模型固定搜索吞吐：rank=0/8/16/32 分别为 166106/161168/156705/150927 simulations/s，即相对成本约 0%/3.0%/5.7%/9.1%。早期 `[hidden, rank]` 标量实现的约 40% 损失已由 `[rank, hidden]` 连续布局和 SIMD 消除。
- 固定开局集 Arena：rank=32 对 rank=0 为 0 Elo（24/16/24）；中残局集为 -16.3 Elo（27/7/30，95% 区间 -61.1 到 +28.0）。原先把同一确定性 startpos 重复 32 次得到的 64/64 全胜不构成独立证据，评测器已改为 startpos 只运行一组换色对局；修正后的合并结果为 -2.7 Elo（53/23/54，95% 区间 -49.3 到 +43.9）。
- Pikafish 固定标签评测中，rank=32 的 raw value MAE 略好（0.2343 对 0.2361），但 64-sim search value MAE 略差（0.2208 对 0.2171），search top-1 也略差（42.11% 对 42.52%）。
- 决策：不默认启用低秩残差，也不围绕它继续调起点比例。下一结构候选应直接改善策略特征之间的交互，同时以不超过约 5% 的 CPU 搜索吞吐损失作为首筛预算。

## 策略结构诊断与最终决策（2026-09-22）

- 组件消融显示 tactical 表是当前策略头最关键的关系来源：完全移除后 64-sim search top-1 从 42.52% 降至 34.63%；共享 factor、accumulator 和 consequence 也都有明确贡献。大型 general exact 表贡献较小但并非无效，完全移除时综合 Arena 约 -14.8 Elo。
- 针对 tactical 的结构缺口，试验了“走法 × 战术签名”中间共享因子。固定 replay 严格 A/B 的未来游戏 policy CE 从 2.77919 改善到 2.76017，但 5-update 同算力自博弈后，1024 个开局和 1024 个中残局、800 simulations 的 4098 盘 Arena 为 -1.9 Elo（95% 区间 -8.9 到 +5.1）；开局 -2.9、中残局 -1.0。该候选未转化为棋力，代码分支已清理。
- tactical 的既有棋子/签名共享因子现在在模型加载或训练同步时预折叠进 exact CPU 表，热路径由两次查表降为一次；这不改变模型输出或训练参数。
- Arena 修复后，确定性的标准初始局面只计一组换色对局，`--positions` 只控制多样化开局和中残局数量，避免重复 startpos 制造虚假置信度。
- 最终网络方案不是盲目增加容量，而是保持当前已验证的 hidden=256、rank=0 结构和专用关系头；低秩残差保留为显式可选实验能力，默认关闭。后续若提出新结构，必须相对本方案取得置信区间为正的分来源 Elo，训练损失改善本身不再作为合入依据。

- 策略上下文扩容：rank-16 吞吐下降约 9.5%；rank-8 吞吐下降约 5.1%，固定回放验证 policy CE 2.44101，差于基线 2.44096。未进入 Arena，否决。
- 价值头额外非线性单元：rank-32 吞吐下降约 10%；rank-16 吞吐成本处于测量噪声内。rank-16 在 514 局首筛中为 +10.1 Elo，但扩大到 2050 局后为 -1.7 Elo，95% 区间 [-9.8, +6.4]；小样本信号未复现，否决。
- 截至本轮，网络结构的可确认棋力提升仍为 0 Elo。所有候选默认关闭；实验实现只用于复现和后续消融，不改变生产网络输出。

## Replay 棋形覆盖诊断（2026-09-23）

- 新增 `az-replay-coverage`，对固定 Pikafish 标签局面与 30 万 replay 样本做规范化局面精确匹配，并统计棋子位置特征对在 replay 中的出现频率。
- 精确匹配只覆盖 54/5000 个标签局面，而且这些局面平均保留 31.98 枚棋子；未匹配组平均仅 20.24 枚。精确已见组更低的价值误差主要受开局阶段混杂，不能直接证明“见过即更准”。
- 排除子力数量影响后，在每个相同棋子数内按特征对覆盖度分四分位。最低覆盖组与最高覆盖组的平均棋子数均约 20.4，但 raw policy top-1 为 34.05% 对 38.95%，64-sim search top-1 为 41.49% 对 45.02%，search top-4 为 73.63% 对 77.24%，search value MAE 为 0.2451 对 0.2029。
- 结论：目前出现了比继续加宽网络更明确的“陌生棋形性能下降”相关性，但它仍是观察性证据，不是补数据带来 Elo 的因果证据。下一步只做一次固定算力 A/B：基线继续训练对比按低覆盖度定向加入棋谱标签；使用独立留出标签集和三来源 Arena 验收，若综合 Elo 置信区间不为正则停止该方向。
