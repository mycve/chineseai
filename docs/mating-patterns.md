# 象棋杀法识别：范围、来源与标签约定

研究日期：2026-11-02。本文件记录首批识别范围及后续扩展方向，不宣称穷尽所有杀法。杀法分类没有统一数量：不同教材会拆分变体、合并同义词，部分名称还描述得子或连续攻杀过程，而非最终将死形状。[XQinEnglish 的教材分类比较](https://www.xqinenglish.com/index.php?Itemid=522&catid=207&id=100&lang=en&option=com_content&view=article)

## 判定边界

- 首批识别终局棋盘的几何与攻防关系，须双方将帅存在、轮走方被将军且无合法应着。困毙应独立记录，不混入将死杀法。
- 返回多标签。同一终局可以同时属于铁门栓、白脸将和车将死；具名杀法与将军子类型可以重叠。
- 名称不是充分条件：双炮同线不等于重炮杀，马在指定点不等于对应杀法。需要检查真实攻击、炮架、马腿及将帅合法逃格。
- “严格子集”表示工程上明确选定的可验证形状，不表示覆盖该杀法的全部传统用法。局面未命中标签不等于没有杀法。
- 以下坐标为本仓库公开着法坐标：`a0` 为红方左下角，`i9` 为黑方右上角。内部棋盘数组行号方向相反，勿直接把数字 rank 当数组行号。

## 首批 18 个标签

这组标签同时含命名杀法和基本将军类型。后者方便检查覆盖率，并为以后训练保留比名称更稳定的事实标签。

| 标签 | 中文 | 首批工程范围 |
| --- | --- | --- |
| `DoubleCannon` | 重炮 | 将军炮与敌将同线，唯一炮架为己方另一炮；全局已将死。横向、纵向均可。 |
| `HorseCannon` | 马后炮 | 将军炮以己马为唯一炮架，马与将同线且相距两格，该马还独立封锁一个逃格；横向、纵向均可。 |
| `IronBolt` | 铁门栓 | 中炮实际钉住防守子，车或兵完成将死。通过忽略该炮攻击、保留其占位后的合法防守反事实验证作用。 |
| `SmotheredCannon` | 闷宫 | 炮利用守方士造成的宫内堵塞完成将死；按实现选择的严格士形判断。 |
| `HeavenEarthCannon` | 天地炮 | 底线炮直接将军、中炮实际钉住中路守子的严格子集；其他棋子最后将军的传统变体暂未覆盖。 |
| `TwoSoldiers` | 二鬼拍门 | 两个己兵侵入敌宫两侧肋道并实际参与限制或将军；宫外无关兵不计。 |
| `WhiteFacedGeneral` | 白脸将 | 己将利用将帅不得照面的规则，实际封锁敌将逃路并配合其他棋子将死。 |
| `ElbowHorse` | 卧槽马 | 黑宫受攻时己马在 `c8/g8` 且直接将军；红宫镜像为 `c1/g1`。这是传统卧槽马杀的直接将军子集。 |
| `PalaceCornerHorse` | 挂角马 | 黑宫受攻时己马在 `d7/f7` 且直接将军；红宫镜像为 `d2/f2`。 |
| `AnglerHorse` | 钓鱼马 | 黑宫受攻时己马在 `c7/g7`，实际控制敌将逃格；红宫镜像为 `c2/g2`。 |
| `OctagonalHorse` | 八角马 | 马在敌宫前角并控制逃格：黑宫 `d7/f7`，红宫 `d2/f2`。与挂角位置相同，角色不同。 |
| `DoubleRook` | 双车配合 | 两个车真实参与将军及封锁。标签刻意不用“双车错”，因为终局不能证明此前交替将军的过程。 |
| `SmotheredMate` | 闷杀（终局形） | 敌将宫内相邻格均被守方自己棋子占据的严格形状；不据此反推此前存在诱堵或献子过程。 |
| `DoubleCheck` | 双将 | 同时存在至少两个将军子。与任何命名杀法可重叠。 |
| `HorseCheck` | 马将死 | 最终将军子包含马。 |
| `RookCheck` | 车将死 | 最终将军子包含车。 |
| `CannonCheck` | 炮将死 | 最终将军子包含炮。 |
| `SoldierCheck` | 兵卒将死 | 最终将军子包含兵或卒。 |

重炮的同线炮架及横纵变体参见 [Xiangqi.com 重炮课](https://www.xiangqi.com/strategy/double-cannon)。卧槽与挂角的落点参见 [卧槽马课](https://www.xiangqi.com/strategy/elbow-horse)、[挂角马课](https://www.xiangqi.com/strategy/palcorner-horse)。该站字母用于横行、数字用于纵线，与本仓库坐标不能直接照抄。

闷宫选定范围应与 [闷宫课的士形示例](https://www.xiangqi.com/strategy/smothered-cannon-checkmate)核对；白脸将参见 [将帅限制课](https://www.xiangqi.com/strategy/white-faced-general)。铁门栓、天地炮、二鬼拍门及八角马可在[教练编写的杀法总览](https://www.xiangqi.com/articles/checkmate-strategies)对照其棋子作用。

## 扩展目录及证据等级

| 状态 | 杀法或术语 | 后续需要的证据 |
| --- | --- | --- |
| 终局可定义，待实现 | 高钓马／侧面虎 | 黑宫受攻马位常用 `c6/g6`，红宫为 `c3/g3`；还需检查车马同侧配合、敌将位于肋道及马的实际控格。高钓马有时仅指马位，不能无条件等同整套侧面虎杀法。 |
| 终局可定义，待实现 | 双马饮泉、立马车、双车胁士、老兵搜山 | 分别固定棋子作用与严格变体，避免“两个马／两个车／底兵存在”这样的过宽条件。 |
| 通常需要前后局面 | 拔簧马 | 证明上一着移走了己方蹩马腿棋子，并使原马成为将军子；终局马将军无法证明“拔簧”。 |
| 通常需要着法序列 | 双车错、夹车炮、抽屉杀 | 记录交替将军或闪将过程，不能仅凭最后几个棋子位置命名。 |
| 通常需要着法序列 | 海底捞月／沉底月、金钩马、双杯献酒、送佛归殿／太监追皇上 | 定义牵制、诱离、献子、逼将回位等过程，并区别一般底线攻势。 |
| 通常需要着法序列 | 大刀剜心／大胆穿心、小刀剜心、三车闹士、炮碾丹砂／打剥皮、闷杀 | 需要捕获、献子或堵塞形成的前后证据；有些变体首先是得子技巧，不一定当场将死。 |
| 战略态势，单独研究 | 三子归边、空头炮、重心杀 | 先定义攻势结构、实际参与度与持续过程；不要把笼统阵形当作终局成功奖励。 |

以上同义词与马位用[基本杀法教材目录](https://zh.wikibooks.org/zh-tw/%E4%B8%AD%E5%9C%8B%E8%B1%A1%E6%A3%8B/%E5%9F%BA%E6%9C%AC%E6%AE%BA%E6%B3%95%E5%88%97%E8%A1%A8)交叉核对；较宽泛名称须继续用具名教材棋例确认，不将网络列表数量视作标准。海底捞月的残局专门含义还可参照[深圳市棋国象棋博物馆条目](https://www.xqmuseum.cn/articledetail/220.html)。

## 用例要求

首批测试采用 [Xiangqi Arena 十二种杀法教学](https://www.xqarena.com/zh-hans/guides/checkmate-patterns)页面内嵌的 FEN 与合法演示着法，来源标在 `tests/mating_patterns.rs`。另外补充自主构造的横向马后炮、马位配合和冗余棋子反例。双车错教学例只断言“双车配合”，海底捞月教学例只断言实际将军子，不把教材标题直接当成静态标签。

每项识别至少需要：命中局面、外观相似但有合法应着的反例、无作用的同种棋子反例、左右镜像、红黑翻转。炮类补充零／一／二炮架和横纵变化；马类补充蹩腿与无关马位；铁门栓补充中炮存在但无实际钉住作用的反例。

外部棋图人工转录的 FEN 必须标注“人工转录”，并先由引擎验证双方将帅、将军及合法应着；自行构造的 FEN 则标注“构造用例”。不要将构造用例说成来源原题。将死、困毙、规则判负、缺将、步数截断需分别记录。

## 调用

库接口：`Position::classify_mate() -> Option<MateClassification>`，包含胜方、`Checkmate/Stalemate`、多标签和将军子格号。非终局返回 `None`；困毙返回空杀形标签。支持子的“实际作用”采用必要贡献的保守标准：原局面伪合法将步走完后，唯一攻击来自该支持子；冗余控格可能漏标，不能将未命中视为杀法不可达或没有战术价值。

无需模型即可运行：

```powershell
cargo run --profile fast --offline --bin chineseai -- mate-classify "3aka3/9/9/4C4/9/4C4/9/9/9/4K4 b"
cargo test --profile fast --offline --test mating_patterns
```

自博弈已接入识别统计和独立辅助价值头，下面说明统计和监督口径。

## 开局输入目标并控制落子

现支持 `double-cannon`（重炮）和 `iron-bolt`（铁门栓），中文名称也可用于命令行。目标和执行方在整盘固定，偏好强度为 `0..1`，`0` 或目标 `none` 使用普通争胜策略。命令行未指定执行方时，使用应用 `--move` 后的行棋方；子搜索仍继承该执行方，不能换根就换边。

```powershell
cargo run --profile fast --offline --bin chineseai -- az-search model.safetensors 800 1.0 --mating-target 重炮 --mating-strength 0.8 --mating-side red startpos
cargo run --profile fast --offline --bin chineseai -- az-search model.safetensors 800 1.0 --mating-target 铁门栓 --mating-strength 0.8 --mating-side black startpos
```

GUI／UCI 可以在开局前设置下面三项；设置跨 `position`、双方回合与 `ucinewgame` 保留。黑方执行时须将 `MatingSide` 设为 `black`。

```text
setoption name MatingTarget value double-cannon
setoption name MatingStrength value 0.8
setoption name MatingSide value red
ucinewgame
position startpos
go nodes 800
```

策略网络在原共享表示上增加目标残差编码，仅执行方的策略读取条件表示；对手策略、原 WDL、距离头与 18 个辅助头保持原棋盘表示。一个额外的目标价值头预测**固定执行方**最终完成当前目标的概率，双方节点回传时不取反。MCTS 只在执行方节点加 `0.25 × strength × 目标价值` 的有限偏好，WDL／Q 的输出和胜负证明保留纯胜负语义。已证败路线不能靠目标概率越过更高的胜负证明优先级。

新模型在尚未学出条件策略时，使用一份幅度受限的几何先验帮助布局：重炮偏向双炮同线及接近将线，铁门栓偏向中炮与车兵进宫配合。先验只加入策略 logits 一次，训练、CPU／CUDA 推理和 MCTS 使用同一实现，不把“形状接近”当成目标成功标签或胜负证明。

关闭或必要子力不足时，条件策略、先验及目标奖励均关闭，走法不被额外限制。重炮至少需要己方两炮；铁门栓至少需要己方一炮、一车或兵卒，以及对方尚有可被牵制的将外棋子。这只是不可达的必要条件检查，搜索暂时没找到杀法不代表不可达。执行方已被证明无法获胜时，目标值也归零。普通必胜证明不能直接当成指定杀法成功。

指定杀法是整盘控制条件：第一步起，策略使用目标编码及布局先验，MCTS 使用普通胜负价值加有限目标偏好，自博弈把该搜索策略蒸馏回条件策略网络。目标成功标签只根据真实终局识别；搜索中的目标概率是估计，不执行额外的杀法 AND/OR 证明。原 WDL 和普通胜负证明保留。

带目标也使用原 KLD 收敛停止。执行方根节点首次证明普通必胜后，最多再探索 64 次以寻找更符合目标的胜法，额外次数计入原 simulations 总预算；该短窗口内不由 KLD 提前中断，结束后立即停；已找到真实的指定杀法一手将死则直接停。对手回合或执行方已证不能赢时按普通证明停止。已证胜的候选之间优先目标成功估计最高者，策略标签和温度采样使用相同资格；未证胜时继续按带目标的 MCTS 访问分布学习。有限搜索可能错过更深的指定杀法，不能把停止或低概率解释成严格不可达。

网络分支缓存已恢复：仅在目标、执行方、强度、搜索参数及完整历史相同的情况下复用，切换指令不能复用旧结果。搜索统计与普通证明仍每步重建。边上另存一个固定执行方价值累计量，每条边增加 4 字节。本次调整不改变模型、回放及配置格式，可继续使用已有检查点和数据。

## 目标自博弈训练配置

在本分支生成的配置中设置以下字段；所有顶层字段须放在 `[mating_goal]` 之前：

```toml
format_version = 34
selfplay_opening_book = ""
mating_goal_mix = false
train_value_weight = 1.0
train_policy_weight = 1.0
mating_loss_weight = 0.1
goal_loss_weight = 0.1

[mating_goal]
target = "double_cannon"
side = "red"
strength = 0.8
```

空开局库从标准初始局面自博弈，可以从第一步学习目标路径；非空则使用已有的 FEN 开局库。`target = "iron_bolt"` 切换铁门栓。`mating_goal_mix = true` 时每盘等概率选择普通、重炮或铁门栓，保留配置的执行方和强度，盘内指令不变；混合采样可训练同一模型响应两种目标。不同执行方／强度的覆盖还需采集对应数据，参数支持不等于尚未见过的强度已经训练充分。

样本保留原始指令，策略标签来自该指令下的真实 MCTS 访问分布，不将旧策略标签事后重标成另一目标。真实终局若执行方完成指定杀法，则两方此前局面的 `goal_target` 都为 1；其他已观察结局为 0。未结束、已关闭目标或某个样本时刻已因子力不足而不可达时，该样本 `goal_weight = 0`。后期丢炮导致失败，仍会给此前尚可达的局面提供失败监督。

目标价值采用独立的稳定 BCE 损失，并保留原 WDL、策略和 18 项杀法辅助任务。`goal_loss_weight = 0` 仅关闭目标价值监督，带目标策略仍按 MCTS 标签学习；要做完全普通争胜对照，应同时设置 `mating_goal_mix = false` 和 `target = "none"` 或 `strength = 0`。

TensorBoard 新增 `train/goal_{bce,samples,target_rate,pred_mean,brier}`、留出目标指标，以及 `mating/goal/{重炮或铁门栓}/{attempts,successes,unknown,success_rate}`；进程累计仍使用 `mating_total/goal/*`。成功率分母包含该目标的失败和未知尝试，不能只统计成功样本。未知监督覆盖率应与成功率一起看。

## 自博弈统计与监督

自博弈在搜索证明胜负后继续执行实际着法，直到真正结束或到达原来的 `max_plies`。`terminal.search_proven` 每盘仅计第一次证明，可与实际将死统计重叠，不能与其他终局原因相加作为总盘数。将死和自然步数限制同时触发时，按真实将死计数。

- `mating/{杀法}/count`：本批实际出现该杀法的盘数。一盘对每个标签最多计一次。
- `mating/{杀法}/all_games_rate`：该杀法盘数／本批全部盘数，包含未知或截断盘。
- `mating/{杀法}/checkmates_rate`：该杀法盘数／本批实际将死盘数。
- `mating/{games,labeled_games,checkmates,stalemates,unknown_games,supervision_coverage}`：盘数与实际终局标签覆盖率。
- `mating_total/*`：相同口径的本进程累计指标；进程重启清零，未写入训练进度文件。

18 项可重叠，因此各项比例不必相加等于 1。控制台显示“本批杀法”和两种批内比例。没有对应分母时，TensorBoard 不写入假装已测得的比例。

观察到将死后，把胜方的多热标签回填到该盘胜方的训练局面，败方全为 0。困毙、已观察到的规则胜负／和棋没有命名将死杀形，因此两方各头均为 0、监督权重为 1。步数截断、搜索失败、缺将或只有搜索证明但未看到终局时，监督权重为 0。未带杀形标签的外部 Px0 数据同样为 0 权重，禁止当负样本训练。左右镜像、行棋方 canonical 编码不改变绝对红黑身份的标签归属。

`AzTrainingSample.mating_targets` 和 `mating_weight` 以及目标指令、目标价值标签随回放保存；重放拒绝非有限或越界标签。模型格式已更新为 **54**、回放为 **45**、自博弈配置为 **34**，旧格式会明确拒绝加载；本分支没有旧模型／回放自动迁移。

## 独立多头训练

原有 WDL 保留；18 个线性 sigmoid 读出直接消费策略和 WDL 共用的主干，新增 `mating_output` 和 `mating_bias` 两组参数，不另设私有杀法主干。输出表示**当前行棋方按当前行为策略最终以该杀法将死获胜的概率**，不是条件于获胜的杀法分布，更不是“最优情况下能否强制指定杀法”。搜索的 WDL、Q、胜负证明不使用这些辅助概率，也不会在每个搜索节点计算额外 18 个输出。

辅助损失使用稳定 BCEWithLogits，先对 18 个头取均值，再按样本权重求和并加入总损失。配置 `mating_loss_weight = 0.1`，设为 `0.0` 可做消融；全局权重为 0 或整批标签未知时，从优化目标中断开分支，已有 Adam 动量与权重衰减也不会继续更新杀法读出。共享主干仍会接受其他任务更新，所以停用后预测概率未必固定。

总训练损失沿用按 batch 大小归一的口径，有效监督稀疏时辅助任务强度还会乘有效样本比例。监控 `train/mating_bce` 按有效监督样本数归一，每头记录 `train/mating/{杀法}/{target_rate,pred_mean,brier}`；留出集另记 `test/mating_bce`、`test/mating_samples`。游戏级杀法出现率与行棋方样本目标频率是两种不同统计。

新头初始权重为 0、偏置为 -4。最初先学习读出方向，随后梯度进入共享主干；测试覆盖前向一致、真实自博弈标签的端到端拟合、共享梯度、未知样本屏蔽和关闭后的动量冻结。

## 检验内部表示

```powershell
cargo run --profile fast --offline --bin chineseai -- az-mating-probe --model style.safetensors --baseline control.safetensors --replay experiment.toml.replay.lz4 --split-seed 20261102
```

`--split-seed` 必须与训练配置 `seed` 相同。命令复用训练的整盘 hash 留出规则，过滤未知标签与零 `game_id`，在各分区无放回抽样。若外部回放把不同盘混装进一个 chunk，明确拒绝，以免按样本和按 chunk 划分的结果不一致。

对每个模型分别冻结共享主干，在相同训练样本上重新拟合线性 sigmoid 探针，用训练集均值方差做固定归一化，再在相同留出样本上报告每头正例数、原读出及探针的 BCE／Brier，以及训练频率常数预测器的 Brier。默认训练 2048 个局面、测试 512 个局面、拟合 200 步，均可通过命令参数调整。模型与回放只读，探针仅在内存中训练。

正负样本不齐的头只报告“样本不足”；整个实验无有效头时失败退出。小于常数基线的留出 Brier 说明表示含有可读取信息；只有在同样训练预算、数据与评估样本下优于 `mating_loss_weight=0` 对照，才支持“辅助训练改善内部表示”的结论。探针成功不等于语义解耦，也不能证明模型会按开局指令执行某杀法。本次数值和管线测试不替代长期自博弈实验结果。

命名杀法不是互斥桶，保留原 WDL 和多标签 sigmoid 辅助头。当前形状识别、按行为策略最终形成某杀法的概率、执行指定目标是不同任务；新增条件目标头携带执行方与指令并按固定执行方视角回传，截断和未知终局屏蔽监督。

辅助头可以推动共享主干编码炮架、马腿、宫内堵塞、封锁逃格等信息，但“每个杀法一个输出”本身不保证得到独立、稳定、可控制的内部表示。应分别测未见局面的识别、冻结主干后的探针表现、换指令后的策略变化及真实终局命中率。

子力桶根据当前已知子力选择一个价值分支；未来杀法是未知且可重叠的事件，不能套用这种互斥选桶方式。18 个独立输出使用完整对局的终局标签，新增控制器则让目标进入条件策略与 MCTS，并用该指令下生成的策略标签训练。接通这些链路不代表模型已经学会最优目标策略，仍需实际训练和对照评估。

[UNREAL 原论文](https://arxiv.org/abs/1611.05397)展示了辅助任务共享表征在其测试环境的收益，是尝试辅助头的依据，并非象棋效果保证。[UVFA 原论文](https://proceedings.mlr.press/v37/schaul15.html)提出 `V(s,g)` 的目标条件价值，可作为后续目标编码设计参考。终局标签稀疏和类别不均衡须单独评估；本识别器仅判终局，不应将非终局返回 `None` 当成“未来所有杀法均不可能”的负标签。

## 验证记录

重整后的方向检查：标准初始局面没有已证胜负时，重炮和铁门栓指令均改变前期布局先验、MCTS 访问量及训练策略。另用两个目标各自生成的开局搜索策略，仅训练目标条件编码，不使用任何终局杀法标签或目标价值损失，确认策略交叉熵下降、目标条件参数收到梯度。这验证控制与策略学习链路，开局到终局的实际命中率仍需服务器自博弈对照。

重整后完整回归（2026-11-02）：`cargo test --profile fast --offline --all-targets --quiet`，372 项通过、3 项按原配置跳过。带目标的普通、复用工作区、追踪及受控搜索均用原 KLD 阈值在稳定分布下于 400 次停止，总预算设为 4096 次；这是停止机制检查，实际吞吐需在服务器模型上复测。此前单独启用 `slow-tests` 的 CUDA 条件策略一致性测试也通过。真实铁门栓自博弈终局经 CUDA 完整训练入口进行 12 步最小验证，18 头辅助 BCE 约 0.6848→0.6342，条件目标 BCE 约 4.0182→3.7333。这是单局面的管线可训练性检查，不是完整开局达成率或泛化证据。CUDA／Metal 目标的 `candle-nn` 后端特性与 `candle-core` 同步启用。

实际命令行对照：同一双杀局面普通模式选 `a8e8` 车杀，重炮指令选 `h4e4`；铁门栓指令在另一双杀局面选 `f3f9`。标准开局输入重炮、强度 0.8 后第一步选 `h2e2`。另有真实三半回合重炮测试：搜索在不超过 65 次模拟内放弃普通一手杀，经 `h4h3` 布局；测试另行逐一验证黑方两种合法防守均可由 `h3e3` 形成重炮，目标概率不作为证明。缓存测试核对同一目标下缓存搜索与冷搜索的走法、访问数、策略、WDL、目标值一致，并验证切换目标、执行方或强度会拒绝复用。
