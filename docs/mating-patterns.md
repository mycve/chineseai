# 指定杀法：14 类识别、控制与自博弈训练

名单确认日期：2026-11-02。控制目标、终局标签、辅助头和统计统一使用以下 14 类；不再保留泛化的“车将死、炮将死、马将死、兵卒将死、双将、闷杀终局形、双车配合”分类。不加入三子归边、车马冷着、炮碾丹砂等集结形态或战术过程目标。

## 固定名单与识别范围

所有命中都要求真实将死：双方将帅存在，轮走方被将军且没有合法应着。仅有某种站位、子力数量或网络高概率不算完成目标。杀法是最终致胜机制，一步杀、两步杀是距离，不用固定步数排除某种杀法。

中文名称、连字符键、下划线键可用于 CLI/UCI；“铁门闩”“侧面虎”作为对应别名。TOML 使用下划线枚举名，例如 `high_angler_horse`。`none` 表示普通争胜。

GUI 的 `MatingTarget` 为 UCI `combo` 下拉框：普通争胜及 14 种中文杀法名，一次选一种。默认铁门栓、强度 0.8，开箱启用；手动发送英文键仍可用。更新引擎后需让 GUI 重新读取选项列表；若 GUI 保存了旧的关闭设置，可恢复默认。

标签可以重叠，例如双马饮泉与卧槽马、钓鱼马；不用互斥 softmax 强行分桶。“实际封逃”通过执行敌将的伪合法宫内走子后，检查是否仅该支持子阻止此着来认定；重复控制可能不计，属于明确的保守子集。铁门栓中炮另需验证真实牵制作用。未命中不代表没有其他杀法。

困毙单独记录为 `Stalemate`，不算 14 类目标成功。长将、规则判负、缺将、步数截断、仅有搜索证明都不冒充真实将死。

## 开局输入目标

```text
uci
setoption name EvalFile value multi-v56.safetensors
isready
ucinewgame
position startpos
go nodes 800
```

收到 `readyok` 后搜索，默认已经执行铁门栓目标。切换杀法只需 `setoption name MatingTarget value 马后炮`。`MatingSide` 默认 `auto`：首次 `go` 绑定本盘引擎执子方，之后换根不换执行方，`ucinewgame` 后重新绑定；也可显式指定 `red`/`black`。目标与强度跨 `position`、回合及 `ucinewgame` 保留。强度为 `0..1`，默认 0.8，设 0 或选普通争胜均关闭目标。CLI 的 `az-search` 同样默认铁门栓、0.8，可显式用 `--mating-target none` 做普通对照。CLI 示例：

```text
chineseai az-search multi-v56.safetensors 800 1.0 --mating-target 高钓马 --mating-strength 0.8 --mating-side red startpos
chineseai mate-classify "3aka3/9/9/4C4/9/4C4/9/9/9/4K4 b"
```

策略从第一步读取目标残差编码，配合受限布局先验；目标价值头预测固定执行方最终完成指令的概率。MCTS 在执行方节点使用 `普通 Q + 0.25 × strength × 目标价值 + PUCT 探索项`，目标概率回传不取反。普通 WDL、胜负证明保持原含义，对手正常争胜。强度不是损失权重。

关闭目标或必要子力不足时恢复普通策略：重炮至少两炮，马后炮需马炮，双马饮泉需两马，双车错需两车，二鬼拍门需至少两个车或兵；资源条件只用于认定明确不可达，不把搜索暂未找到当作不可能。目标几何先验只改变策略 logits，不能作为成功标签或杀法证明。

带目标也复用网络分支缓存、使用原 KLD 收敛停止。缓存要求目标、执行方、强度、参数及完整历史一致。执行方根节点首次证明普通必胜后，最多再探索 64 次寻找更符合目标的胜法，计入原总预算；已发现真实的指定杀法一手将死则立即停。目标概率是估计，不执行额外杀法 AND/OR 证明。

## 自博弈采样

新生成的配置已默认启用目标混合与 0.8 强度；下面为显式写法。顶层字段必须放在 `[mating_goal]` 之前：

```toml
format_version = 34
selfplay_opening_book = "book.pgn.gz"
mating_goal_mix = true
train_value_weight = 1.0
train_policy_weight = 1.0
mating_loss_weight = 0.1
goal_loss_weight = 0.1

[mating_goal]
target = "iron_bolt"
side = "red"
strength = 0.8
```

- `mating_goal_mix=true`：约 10% 对局普通争胜，其余 90% 在当前起局仍有必要子力的确认目标中均匀采样；不按网络预测成功率筛选，避免困难目标失去训练机会。若全部目标都已缺必要资源，则恢复普通争胜。
- `mating_goal_mix=false`：固定使用 `[mating_goal].target`。
- 执行方固定用 `[mating_goal].side`，不随机红黑、不增加随机选方开关。canonical 编码共享双方参数，固定执行方的整盘数据也含执行方及对手两种回合。
- 每盘只指定一方执行目标，目标、执行方和强度盘内不变。对手正常争胜。空开局库从标准初始局面开始。

GUI 自动绑定本盘执子方与自博弈固定执行方是入口层约定；都不随机选红黑，也不在搜索子节点中切换执行方。显式保存的配置值优先于新默认，不擅自覆盖用户选择的普通争胜或强度 0。

开局库是既有的可选 FEN 起局来源，不是新增的残局模式。沿用已有开局库即可从所选局面开始执行目标；FEN 之前的着法不属于该盘目标训练样本。这里的混合采样检查只避免为缺炮、缺马等局面分配已明确不可达的目标；不改变开局库配置。手动固定指定目标不被重新随机分配，仍按原规则在不可达时正常下。

自博弈把带指令的 MCTS 策略训练回条件策略，尚无终局标签时也可以学习策略。最终真实完成指定杀法则固定执行方目标标签为 1，其他已观察结果为 0；双方此前局面使用相同执行方视角。截断、未知或样本时刻已无必要子力时，目标价值监督权重为 0。不能把旧策略标签事后重标成另一条指令。

14 个辅助头读出共享棋盘表示，预测当前行棋方最终以相应杀法获胜的概率，使用稳定 sigmoid BCE。`mating_loss_weight` 控制该辅助任务；`goal_loss_weight` 控制条件目标价值任务。目标损失按有效目标样本的权重总和归一化，不再被普通对局、截断或资源不足样本的比例稀释；停用和无标签时仍断开该损失的梯度。正负样本均保持真实分布，目标 CE 下降不等于执行成功率提高。

v56 的条件表示使用轻量乘性门控：基础局面表示为 `h`，执行方/目标对应的一行为 `g`，强度为 `s`，则 `u = h * (1 + s * tanh(goal_scale[g]))`。WDL、距离头读取 `u`；目标价值头和执行方策略读取 `ReLU(u + s * goal_hidden[g])`。对手的策略仍读取基础 `h`，对手 WDL 读取有指令条件的 `u`，学习对手正常争胜时这一对局策略的胜负。辅助杀法头继续读取基础 `h`。没有目标或必要资源已丢失时全部恢复基础表示。

原先只有加性目标偏移，在 ReLU 激活区间不变时，线性目标价值头对不同目标主要只能改变偏置。乘性门控允许重炮、马类等目标分别选择局面特征；它同时接受策略、WDL、距离和目标终局损失的梯度，尚未完成对局时也能通过 MCTS 策略监督学习。新增矩阵只有 `28 * hidden_size` 个参数，不增加配置项；CPU 在权重发布时预计算 tanh，每个节点只读取一行，不增加搜索或证明预算。新门控从零初始化，旧权重迁移后的初始输出保持原行为。

## 模型与回放迁移

当前模型 v56：保留 28 维目标输入、14 个辅助杀法头，新增目标乘性门控。普通加载器只接受当前格式，v54/v55 模型须显式转换，输出文件必须不存在：

```text
mkdir run-v56
chineseai az-upgrade-mating-targets old-v55.safetensors run-v56/model.safetensors
```

v55 转换保留所有已训练权重，新 `goal_scale` 为零，门控初始为恒等变换。v54 转换另将 4 维目标输入扩为 28 维，搬移双方重炮、铁门栓编码，按名称将旧 18 个辅助头重排为确认的 14 类；新增目标编码及辅助读出权重为零，新增辅助偏置为 -4。

回放仍为 v46，本次没有改变杀法标签和指令语义，已有 v46 回放可复用；旧 v45 不支持。模型参数列表增加了门控，旧 AdamW 状态不能直接恢复。训练请复制到新的配置文件路径，设置 `model_path` 为新目录中的转换文件（如 `run-v56/model.safetensors`）、`checkpoint_dir` 为新目录以重建优化器，避免启动器从模型同目录加载旧 `best.safetensors` 或旧 `.adamw.safetensors`。若要复用 v46 回放，将旧 `<配置路径>.replay.lz4` 复制到新配置对应的路径；不要复制旧 `.progress` 或优化器状态。原有学习成果由模型转换保留，新增门控继续学习；无需为了本次结构改动清空可用的 v46 回放。

## 统计与效果判断

控制台只列 14 类命名杀法，显示批内总局数、实际将死、困毙、未知、各目标尝试／成功／未知及“目标执行红/黑”数量。杀法可重叠，计数不应相加作为总盘数。

TensorBoard：`mating/goal/{名称}/{attempts,successes,unknown,success_rate}`、`mating/goal_side/{red,black}/attempts`，累计对应 `mating_total`。训练和留出集记录 `goal_{bce,samples,target_rate,pred_mean,brier}`。目标率分母包括失败和未知尝试。

全局杀法率包含双方，指令成功率只算指定执行方，两者不能直接比较。应在同模型、同开局上对比无指令和指定指令的执行方胜率、命中率，同时记录平均模拟数、每秒模拟数和对局长度。CE 下降及条件策略变化不等于已学会从开局稳定执行指定杀法。

## 验证与来源

完整回归 394 项通过、4 项跳过（含手动性能基准），全部 14 类、双方角色、零/非零门控的 CPU/CUDA 策略、WDL、距离一致性检查通过。v54/v55 权重迁移通过回归；真实旧文件已完成命令行迁移，高钓马命令行搜索、UCI 中文下拉选项、默认启用及黑方自动绑定均已检查。以上验证管线和局部行为，不表示开局完整对局达成率已经通过实验。

```text
cargo test --profile fast --offline --all-targets --quiet
cargo test --profile fast --offline --features slow-tests --lib goal_conditioning_matches_cpu_on_cuda -- --nocapture
```

检查真实命中、无杀反例、无关子反例、左右镜像、红黑翻转；新增全部 14 类关键参与子移除反例及 4 种朝向下的目标执行方/资源屏蔽交叉检查。用户反馈的 `4kR3/9/6N2/9/2b1P1b2/9/9/9/4K4/2B2A3 b - - 0 1` 应归钓鱼马，不能算高钓马成功；其他 App 所用“列马车”等命名不自动并入目标标签。CPU/CUDA 条件编码及策略一致性；回放指令读写；目标采样；模型迁移保留参数。开局测试核对指令对布局先验、MCTS 访问分布和训练标签的影响，并检查不使用终局价值标签时策略监督仍能训练目标编码。局部用例不替代服务器完整对局的命中率实验。

v55 历史性能检查（64 宽随机模型、标准起局、14 种目标、固定 128 次模拟、深度 4）：三次运行中位数，1400 次目标推理从 22.263 ms 降到 12.433 ms；56 次搜索共 7168 次模拟，从 70.324 ms 降到 50.990 ms，结果校验和相同。主要改动为共享布局先验的基准分和可撤销工作棋盘、目标条件输入直接取唯一非零编码行、移除根策略候选中重复的目标资源扫描。此为本地小模型基准，服务器完整自博弈收益须另测。 v56 相同条件三次中位数：普通推理 4.319 ms、目标推理 12.760 ms、搜索 52.722 ms，预算及结果校验和保持相同。门控引入少量逐通道乘加，不能据此保证服务器自博弈耗时完全不变。

## 当前设计取舍与待验证项

- 红黑执行方随机不是正确编码的必要条件，已移除该功能。固定选方可能存在先后手分布差异，评价目标效果时使用同执行方、同开局的配对对照。
- v56 已让 WDL、距离估计也读取目标门控，减少不同指令策略结果被无条件平均的问题。WDL 的标签仍是胜/和/负，应继续比较各目标下的校准，不能把结构接通视为训练已经有效。
- 远期目标的成功监督稀疏，失败预测准确也能降低 BCE。支持 14 类不表示同时均匀训练 14 类就有足够正例；应看正例覆盖、常数频率基线及同开局指令增益，区分手写布局先验与学到的长程控制。
- v56 已将目标损失改为按有效权重总和归一化，`goal_loss_weight` 相同数值的实际贡献会比旧版本更高，幅度取决于有效目标样本比例。例如有效占比约 50% 时，目标分支相对旧实现约为两倍；建议先保留 0.1 做对照，不同时改动多个训练权重。
- 已证普通必胜时，当前最终策略按目标概率最高值筛选；真实目标成功与网络估计的置信度不同，该筛选可能放大未校准估计的噪声。强度连续性、保留探索的软偏好应作为单独对照，不把估计当作杀法证明。
- Arena 当前评估普通争胜，`best` 的选取不衡量杀法指令命中率；自博弈使用最新训练模型，不受 Promote/Reject 阻断。验证控制效果时应使用目标指标配对评估训练检查点，不能仅以 Arena 的 Promote 判定目标能力更好。

- **夹车炮**：[钱俊《象棋中局杀法》](https://www.wxf-xiangqi.org/images/free_download_books/Checkmate_methods_in_Xiangqi_Midgames.pdf)列有车双炮配合。应先确定典型末端构型，并检查三子是否实际参与将军、封逃或掩护；仅有车双炮或三子同翼不足以命中。单个终局不能证明此前发生过连续交替将军。
- **空头炮杀**：炮与敌将同线、两者之间无子，利用炮的作用限制守子回防，再由其他子成杀；需验证真实的禁入或封防作用。[世界象联入门教材](https://www.wxf-xiangqi.org/images/free_download_books/xiangqi_introduction_chessplayers_20150323.pdf)有独立棋例。不能把所有中炮站位算成目标成功。
- **小鬼坐龙庭**：兵卒占据敌方九宫正中，并实际参与配合成杀。名称与站位的对应可见[深圳市棋国象棋博物馆说明](https://www.xqmuseum.cn/articledetail/195.html)；正式实现仍需正例和移除参与子反例。
- **小鬼扼喉**：按已提供的定义，以兵卒占据九宫两肋咽喉点、实际封逃参与成杀作为候选判据。与二鬼拍门的双侧配合区别在于不要求两侧都有兵卒；工程判据与训练目标是否值得独立增加，待确认。

平顶冠保留为二级候选，需固定空头炮与宫前横列子力在最终将死时的具体配合，避免把过程中的“空头”状态误当终局条件。中肋炮暂缓，可靠典型棋例和独立于铁门栓、天地炮的判据还需补充。拔簧马、白马现蹄、海底捞月、炮碾丹砂等涉及历史过程，不仅凭最终 FEN 反推。
