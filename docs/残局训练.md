# 本地残局教师训练

本地 Pikafish 残局教师直接接入原有 `az-loop`，默认开启。训练不请求云库，不需要手工生成标签；模型和回放文件格式不变。

## 直接训练

沿用原来的 `az-loop` 命令和原配置。使用默认配置路径时：

```powershell
.\target\fast\chineseai.exe az-loop
```

原来指定了 TOML 路径的，继续指定同一路径即可。旧配置没有 `endgame_teacher_*` 字段时会采用本地教师默认值；已有模型路径、搜索预算、学习率、回放和检查点配置按原值读取，不重写配置文件。显式设置 `endgame_teacher_enabled = false` 可关闭教师。

教师默认使用项目目录的 `tools/pikafish.exe`、`tools/pikafish.nnue`，启动时实际浅搜确认网络能加载。训练至指定更新并保存仍使用 `az-loop 原配置.toml --target-update N`。更新编号是绝对编号；重复运行已完成的目标会直接返回。

`az-train` 和 `tools/train.ps1` 是可选的独立实验准备工具，会建立 `training/local-endgame.toml` 及隔离产物目录；使用残局教师不要求切换到它们。

默认保留项目的正式搜索和预热预算（10000 次模拟、600000 个预热样本），首个更新前需要持续产数。快速验收使用独立的小型配置，不降低正式训练预算。

## 教师怎样解决残局标签问题

模型正常自博弈到总棋子数不超过 12（包含将帅）时，本地 Pikafish 接管双方，直到本引擎判定实际终局。教师走法同时生成一热策略目标，终局胜负向该局所有样本回传，使前面的局面不再由弱模型的残局落子决定结果。网络因此同时学习如何完成残局，部署时仍可独立搜索。

教师沿用完整起始 FEN 和着法历史，每一步通过 `searchmoves` 限定为本引擎认可的合法着法。只使用教师的走法，不把 cp/mate 分数当作精确 WDL 或搜索证明。标签代表这条混合策略实际完成的对局结果，并不保证理论最优。

默认最多 2 个持久教师进程，每进程 1 线程、64 MiB Hash、每步 20000 nodes、请求超时 30 秒。达到残局接管条件后允许额外最多 600 个教师半回合，不受普通对局剩余预算截断。仍未结束的样本关闭价值及剩余步数损失，保留合法策略监督。协议错误或超时会明确停止训练并回收教师，不把失败写成和棋。

原 `az-loop` 保留已有的起局设置，GEVC 档案重启可单独开启；独立实验预设使用 50% 重启比例。deblunder 默认关闭。即使手动开启，发生教师接管的整局也不做这项校正，避免弱模型 Q 覆盖教师完成的结果。教师预算是有界的工程起点，不是已经验证的最优配置。

## 原 az-loop 的可选机制

除默认开启的本地教师外，LC0 式 deblunder、已验证残局标签重标注和 GEVC 均可独立开启，用于对照实验。

```toml
deblunder_enabled = true
deblunder_q_gap_threshold = 0.1
deblunder_q_gap_width = 0.0

restart_fraction = 0.5
# 工程内存上限，可按机器资源调整；不预分配全部快照。
restart_capacity = 10000

# 没有本规则下的已验证标签时保留空字符串。
tablebase_sqlite = ""
```

deblunder 比较实际搜索最佳着法与实际落子的 Q；只有两者都被访问、WDL 有效且存在已知结果时才校正。使用最佳着法的 WDL，而不是根 WDL 或未访问走法的 FPU。较晚的估计不会覆盖已证明标签，也不会越过证明边界。受校正影响的剩余步数损失被关闭，因为实际旧轨迹的长度不再代表替代策略的长度。

GEVC 从最近访问的非终局局面中均匀抽取起点。每条轨迹结束后发布局面，所有自博弈线程共享有界循环档案。完整保留历史、自然限着计数和模型代数；重启温度及单次对局预算按局部步数计算，阶段统计保留原始步数。档案目前在进程重启后重新积累，空档案自动使用正常起局。原项目的开局库、搜索及温度曲线继续使用，故这是 GEVC 起局方法的接入，而不是论文全部实验配置的复现。

## 已验证残局标签

运行期只读本地 SQLite，不在自博弈线程访问网络。查询必须精确匹配棋盘、完整规则历史、自然限着设置和规则版本。标签可以向本次轨迹前缀传播，但只有命中局面本身是精确锚点；不会把传播后的中局标签当成搜索证明，也不会写入 MCTS `solved`。

可先用现有证明器生成小型缓存。UTF-8 输入文件每行一个 FEN；已有对局历史时，使用 `起始FEN<TAB>空格分隔的UCI着法`，工具会重建完整历史。

```powershell
cargo run --profile fast --offline --bin tablebase_verify -- eval/endgames.fens eval/endgames.sqlite --max-plies 15 --max-nodes 200000 --rule60-max-ply 120
```

工具只写入本引擎判定的终局或已经证明的连将强制胜。未证明、超预算都记为 unknown，不标成和棋。连将搜索距离不是完整 DTM，因此非终局胜标签不训练剩余步数。生成非空标签库后，设置 `tablebase_sqlite = "eval/endgames.sqlite"`；规则或上下文不匹配不会命中，仅含未验证数据的库会在启动时明确报错。

FEN 独立行代表新的起局历史，不能替代实际对局的历史。`tablebase_verify` 是有限范围的证明工具，不是完整残局库生成器。规则实现改变后须递增 `TABLEBASE_RULESET`，重新验证对应标签。

## 外部云库候选缓存

```powershell
uv run --no-project tools/import_xiangqi_tablebase.py eval/endgames.fens eval/cdb-candidates.sqlite --metric dtm --limit 1000
```

只调用 CDB `queryall&learn=0`，设置超时和请求间隔，已有响应默认跳过。普通引擎分数不会推断为 WDL；只有明确 EGTB 标记的着法进入外部候选表。CDB 的 AXF 结果未自动证明与本项目规则等价，故 `cdb_labels` 与 `verified_labels` 隔离，导入不会直接增加训练标签。可把相同候选 FEN 交给上述本地证明工具，有限范围外的残局仍需其他规则一致的验证器。

云库导入和证明缓存属于可选研究工具，一键训练不依赖它们。当前仓内的 Pikafish 及其 SQLite 评估集不是完整残局库。

## 观测与验证

TensorBoard 新增 `selfplay/teacher_games`、`selfplay/teacher_samples`、`selfplay/teacher_completed`，分别统计接管对局、教师策略样本、教师完成的真实终局；另有 `selfplay/deblunder_triggers`、`selfplay/deblunder_samples`、`selfplay/tablebase_hits`、`selfplay/tablebase_samples`、`selfplay/restart_archive_size`。起局统计的现有 `Midgame` 槽位表示档案重启，包含中局和残局。

```powershell
cargo test --profile fast --all-targets --offline
cargo test --profile fast --lib local_teacher_rollout --offline -- --ignored --nocapture
cargo test --profile fast --lib local_pikafish_smoke --offline -- --ignored --nocapture
uv run --no-project tools/import_xiangqi_tablebase.py --self-test
```

最终收益仍需固定残局集和固定预算对弈评测；这些实现测试验证标签及规则处理，不测 Elo。
